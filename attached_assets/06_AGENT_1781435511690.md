# AGENT.md

# Rise of the Plants (ROP)

## Replit Agent Operating Guide

Version: 1.0

Purpose:

This document defines how Replit Agent should approach planning, implementation, prioritization, and decision-making throughout development.

This document takes precedence over assumptions made by the agent.

---

# 1. Core Mission

Build a polished, deployable Buildathon submission called:

Rise of the Plants (ROP)

The goal is not to maximize feature count.

The goal is to maximize:

* User delight
* Demo quality
* Visual polish
* Buildathon competitiveness

---

# 2. Success Definition

The project succeeds when a first-time user can:

1. Obtain a starter seed
2. Complete a task
3. Grow a plant
4. Trigger an evolution
5. Unlock a Codex entry
6. Read lore from Sanity
7. Open AR mode
8. Place a plant into their environment
9. Complete a battle
10. Unlock a new species

within approximately 3 minutes.

---

# 3. Product Priorities

Priority order is fixed.

Never reorder without explicit instruction.

---

## Priority 1

Core Gameplay Loop

Task
→ Resource
→ Growth
→ Evolution

This loop must work before anything else.

---

## Priority 2

Codex + Sanity Integration

The world must be powered by Sanity.

Judges should immediately see this.

---

## Priority 3

Evolution Experience

Evolution should be memorable.

This is a primary wow moment.

---

## Priority 4

AR Viewer

Must feel magical.

Does not need advanced WebXR.

---

## Priority 5

Battle System

Simple but polished.

---

## Priority 6

Additional Content

Only after everything above works.

# 5. Buildathon Optimization Rules

The application is being judged.

The application is NOT being prepared for production scale.

Therefore:

Prefer:

* Simplicity
* Reliability
* Polish

Over:

* Scalability
* Microservices
* Complex infrastructure

---

# 6. Technical Decision Rules

When choosing between two solutions:

Choose the solution that:

1. Ships faster
2. Is easier to demo
3. Creates fewer bugs
4. Is easier to understand

---

# 7. Architecture Rules

Sanity is mandatory.

Sanity is the source of truth for:

* Species
* Lore
* Evolutions
* Tasks
* Rewards
* Codex Entries

---

Player Progress:

Use localStorage.

Do not introduce unnecessary backend persistence.

---

# 8. Design Rules

The game should feel:

* Magical
* Cozy
* Optimistic
* Rewarding

Avoid:

* Corporate dashboard aesthetics
* Cyberpunk themes
* Generic SaaS design
* Enterprise UI patterns

---

# 9. Mobile First Rule

Assume judges will test on phones.

Every feature must work well on:

* Mobile browsers
* Touch interfaces
* Small screens

Desktop optimization is secondary.

---

# 10. Development Methodology

Development should occur in phases.

Do not jump ahead.

Do not partially build multiple systems.

Finish each phase before beginning the next.

# 12. User Experience Rules

Every screen should answer:

"What should I do next?"

within 3 seconds.

The user should never feel lost.

---

# 13. Evolution Rules

Evolution is a major emotional reward.

Evolution must include:

* Visual transformation
* Particle effects
* Rarity reveal

Never make evolution feel like a simple stat increase.

---

# 14. Codex Rules

The Codex is one of the most important screens.

Purpose:

Demonstrate structured content.

Each entry should display:

* Name
* Description
* Lore
* Habitat
* Evolution Path
* Rarity

All content should come from Sanity.

---

# 15. AR Rules

AR should prioritize reliability.

Preferred:

Camera Overlay AR

Acceptable:

WebXR when available

Do not delay shipping for advanced AR features.

---

# 16. Performance Targets

Initial Load:

Target < 3s

Maximum 5s

---

Navigation:

Target < 500ms

---

AR Startup:

Target < 5s
